# 운전 모드·상태·판정 규격

모드 번호, 우선순위, 판정 클래스는 모든 모듈이 같은 값을 써야 합니다.
파이썬 쪽 기준 값은 `common/protocol.py`, micro:bit·아두이노는 이 표를 보고 맞춥니다.

## 1. 운전 모드

2026-11-28 변경: 실제 제어 코드(`code/microbit`)에 맞춰 3 = 일시 정지를 쓰고, 도움 요청은 모드가 아니라 따로(`help`) 보낸다.

| 번호 | 모드 | 벨트 (우노 모드 핀) | 4대 LED | 수신호 (WonderCam 학습 ID) · 손 3·4 복창 | 작업 손(1·2) |
| --- | --- | --- | --- | --- | --- |
| 1 | 자동 | 보통 속도 (`01`) | 초록 | OK 사인 | 판정대로 분기 |
| 2 | 저속 | 느리게 (`10`) | 노랑 | 손가락 2개 (V) | 판정대로 분기 |
| 3 | 일시 정지 | 멈춤·잠김 (`00`) | 빨강 | 주먹 | 그 자리 멈춤 (받은 판정은 기억했다가 1·2에서 적용) |
| 4 | 점검 잠금 | 멈춤·잠김 (`11`) | 빨강 깜빡임 | 손바닥 활짝 (+ 손목 회전) | 날개판을 벨트와 나란히 접고 멈춤 |
| (도움 요청, 선택 S1) | 모드와 별개 (`help` = 1) | 그대로 | 손 4만 파랑 + 호출음 | 카드 5 또는 손 3 로고 터치 · 손 4 손가락 흔들기 | 그대로 |

- 모드 입력: 손 3의 WonderCam 수신호(기본) 또는 숫자 카드(로고를 길게 눌러 전환). 번호는 같다. 노트북 손짓(MediaPipe)은 아직 연결하지 않았다.
- 모드의 기준은 손 3이다. 손 3이 0.3초마다 `mode`를 보내고, 게이트웨이가 이것을 모드 핀으로 우노에 넘긴다. 노트북은 받은 모드를 **기록만** 한다.
- 파이썬 기준 값: `common/protocol.py`의 `Mode`.

### 내려가기와 올라가기 (손 3이 판단)

- **멈추는 쪽은 바로**: 저속(2)·일시 정지(3)는 약 0.5초, 점검 잠금(4)은 약 1초 연속 보이면 적용.
- **다시 켜는 쪽은 확인 뒤에**: 1·2로 올라가려면 같은 수신호를 3초 유지(프레임 80% 이상) → 접근 위험 0 → 3초 예고 → 모드 변경. 그 뒤 우노는 **리셋 버튼**을 눌러야 돈다. 노트북은 끼지 않는다.
- 점검 잠금(4) 중에는 수신호·카드로 바꿀 수 없다. 손 3의 A+B 버튼으로만 푼다.

## 2. 안전 단계 (danger level)

| 단계 | 감지 | 반응 | 풀리는 방법 |
| --- | --- | --- | --- |
| 0 정상 | | 모드대로 | |
| 1 접근 경고 | 손 3 초음파, 주의 거리 안 (`safety.warn_distance_cm`, 40), 연속 3번 | 라디오 `dng` = 1, 손 3·4 "멈춰" 손짓 + 경고음. **벨트 속도는 지금 바뀌지 않는다** (아래 참고) | 사람이 떠나면 자동 복귀 |
| 2 위험 정지 | 초음파 정지 거리(20) → 손 3이 모드 3(일시 정지)으로 바꿈 → 모드 핀 `00`, 손 3 신호·하트비트 끊김, 비상정지, (선택) IR 커튼 | 벨트 즉시 정지·잠김, 4대 빨강, 연속음, 신호 손 주먹, 작업 손 그 자리 | 원인이 사라져도 안 켜짐 → 카드·수신호 1·2 + 리셋 버튼 |

- 오경보 필터(짧게 스친 감지 무시)는 **1단계에만**. 2단계는 한 번만 감지해도 멈춘다.
- **미정 (팀 결정 필요)**: 예전 규격은 "접근 경고 = 저속"이었지만, 지금 게이트웨이는 `dng`를 모드 핀에 반영하지 않는다. 저속이 필요하면 손 3이 경고 때 모드 2를 보내거나 게이트웨이가 `dng` = 1일 때 핀을 `10`으로 내리도록 micro:bit 코드를 고쳐야 한다 (안전 경로 변경 → 정지 시험 다시).

## 3. 우선순위

```
위험 정지(dng 2) > 점검 잠금(mode 4) > 일시 정지(mode 3) > 접근 경고(dng 1) > 저속(mode 2) > 자동(mode 1)
```

높은 쪽이 걸려 있으면 낮은 쪽 표시는 가린다. app의 상태 계산(`effective_state`, 대시보드 표시)은 이 순서를 따른다.

## 4. 판정 클래스

모델은 사진 전체를 **4클래스**로 분류한다(탐지 아님). 판정은 **웹캠이 병 도착을 감지해 벨트를 멈춘 뒤**(IR 도착 센서는 나중에 보조) **1프레임**(`vision.frames`)을 찍어서 한다. 판정 사진은 감지한 병 둘레를 자른 것(`vision.crop_mode: box`) 또는 판정 구역 전체(`roi`).

### 모델 구성 (2026-11-26, `vision.model_mode: split`)

4클래스를 모델 하나로 바로 내지 않고, **두 모델의 결과를 합쳐서** 만든다 (`vision/bottle/classifier.py`).

| 모델 | 클래스 | 가중치 (`settings.yaml`) |
| --- | --- | --- |
| 색 모델 | `clear`(무색 투명) / `color`(유색·불투명) | `vision.color_model.weights` (초안 `training/weights/color_best.pt`) |
| 라벨 모델 | `label`(라벨 있음) / `nolabel`(라벨 없음) | `vision.label_model.weights` (초안 `training/weights/label_best.pt`) |

- 4클래스 = `<색>_<라벨>` (예: `clear` + `label` → `clear_label`). 판정 코드는 아래 표 그대로.
- 판정 신뢰도: 유색이면 색 모델 신뢰도만, 투명이면 두 모델 중 **낮은 값**. 그래서 투명 병은 라벨 모델이 확신하지 못하면 재검사(`RE`)가 된다.
- 두 모델의 결과는 `pet/judgment`의 `detail`에 따로 남긴다.
- 모델 클래스 이름이 다르면 `vision.*_model.names`로 맞춘다. 맞지 않으면 불러올 때 오류가 난다.
- 가중치 파일이 없으면 모든 병이 재검사(`RE`)가 되고 대시보드에 "가중치 없음"이 뜬다.
- 비교용으로 예전 4클래스 모델 하나(`vision.model_mode: single`, `vision.weights`)도 쓸 수 있다.

| 4클래스 (기록 이름) | 뜻 | 판정 코드 | 분기 |
| --- | --- | --- | --- |
| `clear_nolabel` | 투명·라벨 없음 | `OK` | 벨트 끝 투명 페트 통 |
| `clear_label` | 투명·라벨 있음 | `NG` | 2단계: 손 2 → 부적합 슈트 |
| `color_nolabel` | 유색·라벨 없음 | `CO` | 1단계: 손 1 → 기타 플라스틱 슈트 |
| `color_label` | 유색·라벨 있음 | `CO` | 1단계: 손 1 → 기타 플라스틱 슈트 |
| (신뢰도 < `vision.conf_threshold`, 초안 0.6) | 재검사 | `RE` | 손 2 → 부적합 슈트 |

### 2단계 분기

```
병 ─→ [1단계: 손 1] ─ 유색·불투명(CO) ─→ 기타 플라스틱 슈트
            │ 투명
            ↓
      [2단계: 손 2] ─ 라벨 있음(NG) 또는 재검사(RE) ─→ 부적합 슈트
            │ 투명·라벨 없음(OK)
            ↓
      벨트 끝 투명 페트 통
```

- 1단계는 **색**만 본다. 유색 병은 라벨 여부와 상관없이 먼저 기타 플라스틱으로 보낸다(라벨 여부는 기록만 한다).
- 2단계는 남은 투명 병 중 라벨이 있는 병을 부적합으로 보낸다. 라벨 없는 투명 병만 통으로 간다.
- 4클래스 이름·판정 코드·신뢰도는 분기와 상관없이 병마다 모두 `pet/judgment`로 기록한다.
- 내용물(잔여 음료)은 클래스로 두지 않는다. manifest의 `has_content`는 데이터 관리용 속성으로만 남긴다.
- 클래스를 추가·삭제하면 이 표, `common/protocol.py`의 `CLASS_TO_CODE`, 학습 manifest를 같이 고친다.

## 5. 병 한 개의 흐름 (app 상태 머신)

```
IDLE ─(웹캠: 병이 판정 구역에 완전히 들어옴 → PAUSE)─┐
     ─(IR 도착 센서: EVT,ARRIVE, 선택)──────────────┼→ SETTLE ─(app.settle_ms)→ CAPTURE ─(1프레임 판정, 사진 저장, pet/judgment)
     ─(대시보드 '지금 촬영')────────────────────────┘
CAPTURE ─(app.sorting: false)───────────────────────────────────→ RESUME_WAIT
        ─(app.sorting: true, 게이트웨이에 J0~J4)→ WAIT_ACK ─(ACK,순번,판정)┘
RESUME_WAIT ─(app.resume_delay_ms 뒤 GO = 자동 출발)→ LEAVE ─(판정 구역이 비어 있음 clear_frames)→ IDLE
```

- 웹캠 감지: 빈 벨트 기준 사진과 비교해 판정 구역 안의 물체가 가장자리에 닿지 않은 상태가 `vision.detect.stable_frames` 이어지면 도착 (`vision/bottle/detect.py`). 벨트가 RUN일 때만 멈춘다.
- `LEAVE`: 판정한 병이 구역을 빠져나갈 때까지 같은 병을 다시 판정하지 않는다.
- `WAIT_ACK`: 게이트웨이의 `ACK,순번,판정`(라디오로 보냈음)을 `app.ack_timeout_ms`(기본 1500) 안에 못 받으면 1번 다시 보내고, 또 실패하면 `HOLD` + 대시보드 오류 기록(`NO_ACK`).
- 손은 완료 신호를 보내지 않는다. 날개판이 도는 시간(약 0.4초)은 `app.resume_delay_ms`(2초) 안에 끝난다고 보고 ACK 뒤 바로 `RESUME_WAIT`.
- `OK`(적합)도 보낸다. 손 1·2가 날개판을 나란히 돌려 놓아야 하기 때문이다.
- 위험 정지·일시 정지(3)·점검 잠금(4)이 걸리면 어느 상태에서든 `IDLE`로 돌아가고, 진행 중이던 병 id는 `aborted`로 기록한다. 재가동 뒤 그 병은 사람이 꺼내 다시 넣는다.

## 6. 작업 손(1·2) 동작

손 1·2는 상태 메시지를 보내지 않는다. 동작은 `code/microbit/hand12_sorter.ts`가 기준이다.

| 받은 것 | 동작 |
| --- | --- |
| `jdg` (자기 담당 판정) | 손목을 돌려 날개판을 벨트 위로 비스듬히 (30~45°, 분기) |
| `jdg` (그 밖의 판정) | 날개판을 벨트와 나란히 (통과) |
| `mode` 3 또는 손 3 신호 끊김(2초) | 그 자리 멈춤. 그 사이 받은 판정은 기억했다가 1·2가 되면 적용 |
| `mode` 4 | 날개판을 나란히 접고 멈춤, 기억한 판정 버림 |

- 날개판은 손목에 고정한 장치라 손가락은 쉬는 자세로 두고 움직이지 않는다.
- 날개판은 다음 판정을 받을 때까지 그 각도를 유지한다.
