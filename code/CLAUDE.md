# 인수인계: 투명 페트병 선별 셀 제어 코드

이 폴더를 이어받아 Claude Code로 작업하는 팀원과 Claude를 위한 문서입니다.
코드가 **무엇을 하는지**는 `README.md`(같은 내용의 `README.txt`)에 자세히 있습니다.
이 문서는 **왜 이렇게 되어 있는지, 무엇이 확정이고 무엇이 미정인지, 고칠 때 무엇을 지켜야 하는지**를 담습니다.
작업을 시작하기 전에 이 문서와 `README.md`를 먼저 읽으세요.

## 1. 프로젝트 한눈에

- 청년 피지컬 AI 과정 3팀 팀 프로젝트. 제출 2026-12-07, 최종 발표 2026-12-10.
- Hiwonder AiHand(micro:bit V2 + 확장보드, 서보 6개) 4대와 아두이노 컨베이어로 만드는 탁상용 **투명 페트병 선별 셀**.
- 노트북 YOLO가 병을 판정하면, 손 1·2가 손목에 고정된 날개판을 돌려 병을 분기한다. 손 3은 숫자 카드로 라인 모드를 정하고, 손 4는 떨어진 곳에서 상태를 보여 준다.

| `microbit/hand3_signal.ts` | 손 3 (WonderCam + 초음파) | 숫자 카드 → 모드 결정·전송, 접근 감지, 손가락 복창. **모드의 기준** |

## 3. 확정된 결정 (바꾸려면 팀 합의 필요)

- **분기 방식**: 손이 병을 집지 않는다. 날개판을 벨트 위에 30~45°로 비스듬히 놓고, 벨트 흐름으로 병을 슈트로 흘려보낸다 (스윙 암 분기). 병을 쳐내는 방식은 배출 방향이 불규칙하고 서보에 무리가 커서 버렸다.
- **날개판은 손목 부분에 장치로 고정한다.** 손에 쥐여 주지 않는다. 그래서 손 1·2의 손가락은 쉬는 자세(`REST_*`)로 두고 쓰지 않는다. 코드에 "쥐기(grip)" 개념을 다시 넣지 말 것.
- **손 역할**
  - 손 1: 유색·불투명 병 분기
  - 손 2: 부적합(내용물 남음·라벨 있음·재검사) 병 분기
  - 손 3: 지시 (카드 인식, 접근 감지)
  - 손 4: 원격 표시
- **숫자 카드 모드표** (팀에서 만든 표 그대로 구현)
  - 1 자동, 2 저속, 3 일시 정지, 4 점검 잠금, 5 도움 요청
  - 모드별 벨트, LED, 손 동작은 `README.md` 5.1절 참고
- **노트북 사용 허용**: YOLO, 대시보드 등 노트북 프로그램은 모두 써도 된다. 단, 노트북은 정지 경로에 넣지 않는다 (아래 6절).

## 4. 임시로 정한 것 (팀이 아직 확인하지 않음)

팀 역할표에 없던 부분을 제어 담당이 임시로 정했다. 팀 결정이 나오면 코드와 README를 함께 고친다.

1. **게이트웨이 micro:bit 추가**: 판정 전달과 아두이노 연결용. 주문서에 넣은 여분 micro:bit V2를 쓴다.
2. **사람 접근 시 동작**: 주의 거리(400mm)에서는 경고만 한다. 정지 거리(200mm)에서는 일시 정지로 바뀌고, 다시 출발하려면 카드 1·2를 새로 보여 줘야 한다.
3. **손 3 버튼**: A 즉시 정지, B 도움 요청 끄기, 로고 터치 도움 요청 켜기, A+B 점검 잠금 해제
4. **점검 잠금 해제**: 손 3에서 A+B → 일시 정지(3) → 카드 1·2로 출발
5. **병 투입 간격**: 날개판은 다음 판정이 올 때까지 자세를 유지한다. 그래서 검사 자리와 손 2 사이에는 병이 한 개만 있어야 한다.

## 5. 검증 상태 (중요)

| 대상 | 상태 |
|---|---|
| `conveyor.ino` | `arduino-cli compile --fqbn arduino:avr:uno`로 컴파일 성공 (프로그램 공간 약 25%). 실물 미시험 |
| micro:bit `.ts` 4개 | **컴파일도 실물 시험도 안 됨.** 확장 소스를 직접 읽고 API를 대조해 작성함 |
| 각도·거리·속도 값 | 전부 임시값 (코드의 ★ 표시). 실물 보정 필요 |

- micro:bit 코드를 처음 MakeCode에 붙여넣을 때 오류가 나면, 그게 첫 번째 확인 결과다.
- 로컬 컴파일을 하려면, 프로젝트 폴더에 `pxt.json`(의존성: `core`, `radio`, `StartbitV2: github:Hiwonder/StartbitV2`, 손 3은 `wondercam: github:Hiwonder/WonderCam`)과 `main.ts`를 두고 `npx makecode build`를 시도할 수 있다. 아직 해 본 적은 없다.
- **VS Code의 빨간 오류는 무시해도 된다.** `basic`, `radio`, `StartbitV2` 등을 찾을 수 없다는 오류는 VS Code에 MakeCode 정의가 없어서 생긴다. 판단은 MakeCode 편집기에서 한다.

## 6. 고칠 때 반드시 지킬 것

### 6.1 통신 규칙은 여러 파일에 똑같이 들어 있다

공유 모듈이 없어서 같은 값이 파일마다 복사되어 있다. 하나를 바꾸면 **해당 파일을 모두** 고친다.

| 바꾸는 것 | 함께 고칠 파일 |
|---|---|
| `RADIO_GROUP` (기본 73) | 4개 `.ts` 전부 |
| 메시지 이름 `mode` `help` `dng` `jdg` | 4개 `.ts` 전부 |
| 판정 번호 0~4의 의미 | `hand12_sorter.ts`(`shouldDivert`), `gateway_bridge.ts`, README, YOLO 쪽 프로그램 |
| 모드 → 핀 비트 (자동 01, 저속 10, 정지 00, 잠금 11) | `gateway_bridge.ts`(`writeModePins`), `conveyor.ino`(`Mode` enum), README |
| 신호 끊김 시간 (손 2000ms, 게이트웨이 1500ms, 아두이노 600ms) | 각 파일. 손 3의 0.3초 전송 주기와 게이트웨이의 0.1초 토글보다 충분히 길게 둘 것 |
| 손가락 자세·`WRIST_LOCK` | `hand3_signal.ts`와 `hand4_display.ts`는 같은 자세를 보여야 함 |

### 6.2 안전 동작을 약하게 만들지 말 것

- **노트북은 정지 경로에 넣지 않는다.** 정지 신호는 손 3 → 무선 → 게이트웨이 → 핀 → 아두이노로만 흐른다.
- **신호가 끊기면 멈추는 구조를 유지한다.** 손 3의 주기 전송이 곧 살아 있음 신호다.
- **멈춘 뒤 저절로 다시 돌지 않게 한다.**
  - 카드는 내렸다가 다시 보여야 인정된다 (`armed` / `REARM_FRAMES`).
  - 아두이노 잠김은 리셋 버튼으로만 풀린다.
- **정지는 감속 없이 즉시** 한다 (`updateTarget()`에서 목표 0이면 속도 0).
- 아두이노 모드 핀은 `INPUT_PULLUP`이다. 선이 빠지면 `11`(잠금)으로 읽혀 멈춘다. 비트 배정을 바꿀 때 이 성질을 잃지 말 것.

### 6.3 micro:bit 코드 작성 규칙

- **MakeCode용 TypeScript다.** Node·브라우저 API는 쓸 수 없다. 파일 하나가 기기 하나의 전체 프로그램이고, `import`는 없다.
- 파일 맨 위에서 **초기화(`StartbitV2.startbit_Init()`, `radio.setGroup`)를 이벤트 등록보다 먼저** 한다. 함수 선언은 아래에 있어도 된다.
- **손 3·4에서는 서보를 "손 동작 루프" 하나만 움직인다.** 여러 루프가 서보를 건드리면 손이 엉킨다. 상태 변수만 바꾸고 루프가 반영하게 할 것.
- 소리는 `control.inBackground`로 감싸서 루프를 막지 않게 한다.

## 7. 확장 API 메모 (소스를 직접 읽고 확인한 것)

- **서보**: `StartbitV2.setPwmServo(StartbitV2.startbit_servorange.range1, 번호, 각도, 시간ms)`
  - `range1` = 180° 범위
  - 서보 1~5 = 엄지~새끼, 6 = 손목 회전
  - 공식 예제 기준 각도: 손 펴기 = 1번 50°, 2~5번 130° / 주먹 = 1번 130°, 2~5번 50°
  - **엄지(1번)는 다른 손가락과 방향이 반대다.**
- **`StartbitV2.startbit_Init()`**
  - 시리얼을 P12/P8(115200)로 돌려서 확장보드 MCU와 통신한다. 그래서 **손 micro:bit에서는 USB 시리얼을 쓸 수 없다.** 노트북과 통신이 필요하면 게이트웨이를 거칠 것.
  - 내부에 2초 대기가 있다.
- **초음파**: `RGBSonar.GETDISTANCE()`
  - 단위는 **mm**, 0은 측정 실패
  - `RGBSonar.SETRGB(RGBSonar.RGBMode.rgb, RGBSonar.RGBNum.all, r, g, b)`로 센서의 LED 2개를 켠다.
  - StartbitV2가 의존성으로 자동으로 불러온다.
- **확장보드 RGB LED**: `StartbitV2.startbit_setPixelRGB(StartbitLights.All, StartbitRGBColors.Green)` 다음에 `StartbitV2.startbit_showLight()`
  - `StartbitLights`, `StartbitRGBColors`는 네임스페이스 없는 전역 enum이다.
- **WonderCam**
  - `wondercam.wondercam_init(wondercam.DEV_ADDR.x32)`: 카메라가 없으면 화면에 "E"를 띄우며 **영원히 기다린다**.
  - `wondercam.ChangeFunc(wondercam.Functions.NumberRecognition)`
  - 매번 `wondercam.UpdateResult()`를 부른 뒤 `NumberWithMaxConfidence()`(1~5), `MaxConfidenceOfNumber()`(0~1)를 읽는다.
- 확장 소스: https://github.com/Hiwonder/StartbitV2 · https://github.com/Hiwonder/WonderCam · https://github.com/Hiwonder/RGBSonar

## 8. 남은 일 (우선순위 순)

1. **MakeCode 붙여넣기 확인**: 4개 `.ts`가 오류 없이 들어가는지 본다.
2. **손 1 실물 시험과 날개판 각도 보정**: 일시 정지 상태에서 A(비스듬히)·B(나란히) 버튼으로 `WRIST_PARALLEL` / `WRIST_DIVERT`를 맞춘다. 손목을 돌렸을 때 날개판이 벨트 위에서 수평으로 도는지 먼저 확인한다.
3. **손 3 접근 거리 보정**: 초음파와 카드 인식 방향을 다르게 배치한다. 같은 방향이면 카드를 내밀 때마다 정지가 걸린다.
4. **YOLO → 게이트웨이 연결**: 병 하나당 `J0`~`J4` 한 줄을 115200bps로 보낸다. 3프레임 연속 같은 결과일 때 확정하고, 신뢰도 0.6 미만은 `J0`(재검사)으로 보낸다.
5. **대시보드**: 게이트웨이가 보내는 `ACK`, `MODE`, `HELP`, `DNG`, `LINK` 줄을 읽어 기록한다.
6. **아두이노 실물 시험**: 시리얼 시험 모드(`T` → `R` → `1`)로 속도와 방향을 정한 뒤 `NORMAL_SPS` / `SLOW_SPS`에 반영한다.
7. (여유 있으면) **병 간격 제한 없애기**: 판정 시각과 벨트 속도로 병별 도착 시각을 계산해, 그때 날개판을 움직이도록 개선한다.

## 9. 작업 방식 약속

- 코드 동작을 바꾸면 **`README.md`와 `README.txt`를 같이** 고친다. 두 파일은 같은 내용이다.
- 각도·거리·속도처럼 실물로 정한 값은 코드 상수에 반영하고, 어떻게 정했는지 커밋 메시지나 README에 남긴다.
- 임시로 정한 것(4절)이 팀에서 확정되면 이 문서의 4절에서 3절로 옮긴다.
- 실물에서 확인한 사실(예: "손목 90°에서 날개판이 벨트와 나란함")은 5절 검증 상태 표에 추가한다.
