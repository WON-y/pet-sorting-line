## 1. 무엇을 만드는가

컨베이어 벨트 위로 지나가는 페트병을 카메라(노트북 YOLO)가 판정하고, 벨트 옆에 놓인 로봇 손이 **날개판**을 돌려 병을 알맞은 쪽으로 흘려보내는 탁상용 선별 셀입니다.

| 병 | 처리 |
|---|---|
| 투명하고 깨끗한 병 | 벨트 끝까지 그대로 통과 (투명 페트 통) |
| 유색·불투명 병 | 손 1이 날개판으로 옆 슈트로 분기 |
| 내용물 남음·라벨 있음 병 | 손 2가 날개판으로 부적합 통으로 분기 |

로봇 손에는 팔이 없어서 병을 집어 옮길 수 없습니다. 그래서 손목 부분에 날개판을 장치로 고정해 두고, 손목을 돌려 날개판을 벨트 위에 비스듬히 놓습니다. 병은 벨트의 흐름에 밀려 날개판을 따라 옆으로 빠집니다 (스윙 암 분기 방식). 손가락은 이 동작에 쓰지 않습니다.

작업자는 손 3의 카메라에 **수신호**(OK 사인·V·주먹·손바닥)를 보여 주는 것으로 라인 전체의 모드(자동, 저속, 일시 정지, 점검 잠금)를 바꿉니다. 도움 요청은 숫자 카드 5나 로고 터치로 합니다. 숫자 카드 1~5로 바꿔 쓸 수도 있습니다. 사람이 벨트에 가까이 다가오면 라인은 스스로 멈춥니다.

## 2. 사용하는 하드웨어

- **로봇 손 4대**: Hiwonder AiHand
  - micro:bit V2 + Hiwonder 확장보드 (보드 위 MCU가 서보를 구동)
  - 서보 6개: 1~5번 = 엄지~새끼손가락, 6번 = 손목 회전
  - 전원 7.5V 어댑터 필요 (USB 전원만으로는 서보가 움직이지 않음)
  - 초음파 센서 (I2C, 거리 + RGB LED 2개)
  - 손 3에만 WonderCam AI 카메라 (I2C, 특징 학습 = 수신호 / 숫자 인식 = 카드)
- **게이트웨이용 micro:bit V2 1개** (확장보드 없이 단독 사용)
- **아두이노 우노** (호환 보드 가능)
- **TB6600 스텝모터 드라이버** + 스텝모터 컨베이어 + 24V 전원
- 리셋 버튼, 비상정지 버튼, (선택) 릴레이 모듈
- **노트북**: YOLO 판정 프로그램 실행 (이 폴더에는 없음)

## 3. 폴더 구조

```
code/
├─ README.md                  이 문서 (깃허브 표시용)
├─ README.txt                 같은 내용의 텍스트판
├─ CLAUDE.md                  인수인계 문서 (결정 사항, 검증 상태, 수정 규칙)
├─ microbit/                  micro:bit 프로그램 (MakeCode JavaScript)
│   ├─ hand12_sorter.ts       손 1, 손 2 공용 - 날개판 분기
│   ├─ hand3_signal.ts        손 3 - 수신호(카드) 지시, 접근 감지 (모드의 기준)
│   ├─ hand4_display.ts       손 4 - 원격 상태 표시
│   └─ gateway_bridge.ts      게이트웨이 - 노트북·무선·아두이노 사이 중계
└─ arduino/
    └─ conveyor/
        └─ conveyor.ino       아두이노 - 컨베이어 속도 제어, 안전 정지
```

`.ts` 파일은 [MakeCode](https://makecode.microbit.org)의 JavaScript 편집기에 붙여넣어 쓰는 TypeScript 코드입니다. 파일 하나가 micro:bit 한 대의 프로그램 전체입니다.

## 4. 전체 동작 구조

```
  [노트북 YOLO]
       │ USB 시리얼 "J0"~"J4" (병 하나당 한 줄)
       ▼
  [게이트웨이 micro:bit] ──핀 P0·P1·P2──▶ [아두이노] ──▶ [TB6600] ──▶ 벨트
       │   ▲
  무선 │   │ 무선 "mode" "help" "dng" (0.3초마다)
 "jdg" │   │
       ▼   │
  [손 1] [손 2]      [손 3: 수신호·초음파] ───무선───▶ [손 4: 원격 표시]
   날개판 분기         모드의 기준                       상태 표시
```

신호는 세 갈래로 흐릅니다.

1. **모드 신호 (누가 무엇을 할지)**
   손 3이 수신호(또는 카드)를 읽어 모드를 정하고, 0.3초마다 무선으로 모두에게 보냅니다. 손 1·2·4와 게이트웨이는 이 신호를 받아 각자 동작을 바꿉니다. 게이트웨이는 모드를 2비트 핀 신호로 바꿔 아두이노에 넘깁니다.
2. **판정 신호 (병이 어디로 갈지)**
   노트북 YOLO → USB → 게이트웨이 → 무선 → 손 1·2. 손 1·2는 판정에 따라 날개판을 비스듬히 놓거나 나란히 접습니다.
3. **살아 있음 신호 (멈춰야 하는지)**
   손 3의 0.3초 주기 모드 전송이 곧 "살아 있음" 신호입니다. 이 신호가 끊기면 손 1·2·4는 스스로 멈추고, 게이트웨이는 아두이노로 가는 핀 토글을 멈춥니다. 아두이노는 토글이 끊기면 벨트를 세우고 잠급니다.
   **노트북은 이 경로에 끼지 않습니다.** 노트북이 꺼져도 정지는 동작합니다.

## 5. 공통 약속

### 5.1 모드 번호 (수신호 ID·숫자 카드 번호와 같음)

| 번호 | 수신호 (WonderCam 학습 ID) | 모드 | 벨트 | LED | 손 3·4 (수신호를 따라 함) | 손 1·2 |
|---|---|---|---|---|---|---|
| 1 | OK 사인 | 자동 | 보통 속도 | 초록 | OK 사인 (3·4·5번 손가락 폄) | 판정대로 분기 |
| 2 | 손가락 2개 (V) | 저속 | 느리게 | 노랑 | 검지·중지만 폄 | 판정대로 분기 |
| 3 | 주먹 | 일시 정지 | 멈춤 | 빨강 | 주먹 | 그 자리 멈춤 |
| 4 | 손바닥 활짝 | 점검 잠금 | 멈춤, 수신호·카드로 재가동 불가 | 빨강 깜빡임 | 활짝 + 손목 돌림 | 날개판 접고 멈춤 |
| 5 | (카드 5 또는 로고 터치) | 도움 요청 | 그대로 | 손 4만 파랑 + 호출음 | 손 4가 손가락 흔들기 | 그대로 |

> 학습 ID 5는 빈 배경, 6·7은 "사람만 서 있음"(선택)으로 학습하며 "없음"으로 처리합니다. 손 3이 수신호를 읽으면 벨트 속도(모드)는 게이트웨이 → 아두이노로, 날개판 동작(멈춤·접기)은 손 1·2가 같은 무선 신호를 받아 바뀝니다. 날개판의 분기 각도 자체는 YOLO 판정이 정합니다.

> 코드 안에서 `mode`는 1~4만 쓰고, 도움 요청은 `help`(0/1)로 따로 보냅니다. 도움 요청 중에도 원래 모드(자동/저속 등)가 그대로 유지되게 하기 위해서입니다.

### 5.2 판정 번호

| 번호 | 판정 |
|---|---|
| 0 | 재검사 (YOLO가 확신하지 못함) |
| 1 | 투명 적합 |
| 2 | 내용물 남음 |
| 3 | 라벨 있음 |
| 4 | 유색·불투명 |

### 5.3 무선(micro:bit radio) 메시지

모든 기기는 같은 무선 그룹(`RADIO_GROUP`, 기본 73)을 써야 합니다. 메시지는 `radio.sendValue(이름, 숫자)` 형식입니다.

| 이름 | 보내는 쪽 | 값 | 의미 |
|---|---|---|---|
| `mode` | 손 3 | 1~4 | 현재 모드 (0.3초마다 반복) |
| `help` | 손 3 | 0 / 1 | 도움 요청 꺼짐 / 켜짐 |
| `dng` | 손 3 | 0 / 1 / 2 | 접근 위험: 정상 / 주의 / 정지 거리 |
| `jdg` | 게이트웨이 | 순번 × 10 + 판정번호 | 병 판정 (예: 순번 57, 판정 4 → 574) |

`jdg`는 무선 손실에 대비해 같은 값을 20ms 간격으로 3번 보냅니다. 받는 쪽은 순번(값 ÷ 10)이 직전과 같으면 무시해서 한 번만 처리합니다.

### 5.4 노트북 ↔ 게이트웨이 시리얼 (USB, 115200bps, 줄 단위)

**노트북 → 게이트웨이**: `J0`, `J1`, `J2`, `J3`, `J4` (J + 판정번호)

**게이트웨이 → 노트북**

| 줄 | 의미 |
|---|---|
| `ACK,순번,판정` | 판정을 무선으로 보냈음 |
| `MODE,n` | 모드가 n으로 바뀜 |
| `HELP,0` / `HELP,1` | 도움 요청 꺼짐 / 켜짐 |
| `DNG,0` / `1` / `2` | 접근 위험 단계가 바뀜 |
| `LINK,OK` / `LINK,LOST` | 손 3 신호를 받기 시작함 / 끊김 |
| `ERR,받은내용` | 형식이 틀린 줄 |

### 5.5 게이트웨이 → 아두이노 핀 신호

P0 = 모드 비트 0, P1 = 모드 비트 1, P2 = 살아 있음 토글(0.1초마다 0↔1)

| 모드 | P1 | P0 | 아두이노가 읽는 값 |
|---|---|---|---|
| 자동 | 0 | 1 | NORMAL (보통 속도) |
| 저속 | 1 | 0 | SLOW (느리게) |
| 일시 정지 | 0 | 0 | STOP |
| 점검 잠금 | 1 | 1 | LOCK (멈춤) |

아두이노는 이 핀들을 내부 풀업(`INPUT_PULLUP`)으로 읽습니다. 선이 빠지면 두 비트가 모두 1이 되어 LOCK(멈춤)으로 읽힙니다. 살아 있음 토글도 멈추므로 아두이노는 잠김 상태가 됩니다.

## 6. 파일별 상세 설명

### 6.1 `microbit/hand12_sorter.ts` (손 1, 손 2 공용)

**역할**
손목 부분에 고정된 날개판을, 판정에 따라 손목(6번 서보)을 돌려 "비스듬히(분기)" 또는 "나란히(통과)"로 놓습니다. 손가락은 시작할 때 쉬는 자세로 한 번 맞춘 뒤 움직이지 않습니다. 파일 맨 위 `HAND_ID`를 1 또는 2로 바꿔서 손 1과 손 2에 각각 올립니다.

**분기 규칙** (`shouldDivert()`)
- 손 1: 판정 4(유색·불투명)이면 분기
- 손 2: 판정 0(재검사), 2(내용물), 3(라벨)이면 분기
- 나머지 판정에는 날개판을 나란히 둡니다.

| 판정 | 손 1 날개판 | 손 2 날개판 | 병이 가는 곳 |
|---|---|---|---|
| 1 투명 적합 | 나란히 | 나란히 | 벨트 끝 (투명 페트 통) |
| 4 유색·불투명 | 비스듬히 | 나란히 | 손 1 쪽 슈트 |
| 0, 2, 3 | 나란히 | 비스듬히 | 손 2 쪽 부적합 통 |

**움직여도 되는 조건** (`canMove()`)
① 손 3 신호가 살아 있고, ② 모드가 자동·저속일 때만 날개판을 움직입니다. 하나라도 아니면 판정을 "대기 판정(`pendingTarget`)"으로 기억해 두었다가, 조건이 다시 맞으면 그때 적용합니다.

**모드별 동작** (`onModeChange()`)

| 모드 | 동작 |
|---|---|
| 자동·저속 | 대기 판정이 있으면 적용 |
| 일시 정지 | 아무것도 하지 않음 (그 자리 멈춤). 이후 받은 판정은 대기 |
| 점검 잠금 | 날개판을 나란히 접고, 대기 판정을 버림. 판정을 받아도 무시 |

**신호 끊김**
`mode` 메시지를 받을 때마다 시각을 기록합니다. 2초(`LINK_TIMEOUT_MS`) 동안 오지 않으면 신호 끊김으로 보고 움직임을 멈춥니다. 이때 LED는 보라색, 화면에는 "?"가 뜹니다. 신호가 돌아오면 대기 판정을 적용하고 이어서 동작합니다.

**버튼**
날개판 각도를 맞출 때 쓰는 버튼입니다.
- A: 손목을 비스듬히(분기) 위치로 돌림 (화면에 ↗)
- B: 손목을 나란히(통과) 위치로 돌림 (화면에 ↑)
- 벨트가 도는 중(자동·저속)에는 두 버튼 모두 무시됩니다. 동작 중에 날개판이 엉뚱한 위치로 가는 것을 막기 위해서입니다.
- 일시 정지 중에 A로 시험했다면, 다시 출발하기 전에 B로 나란히 위치에 돌려 두세요.

**화면·LED**
- 시작 시 손목을 나란히 위치로 돌리고 `HAND_ID`를 표시합니다.
- 판정을 받으면 판정 번호를 표시합니다 (날개판을 먼저 움직인 뒤 표시).
- LED 색: 초록 자동 / 노랑 저속 / 빨강 정지 / 빨강 깜빡임 잠금 / 보라 신호 끊김
- LED는 초음파 센서의 RGB LED와 확장보드 RGB LED에 같이 냅니다.

**주요 설정값**

| 상수 | 기본값 | 의미 |
|---|---|---|
| `WRIST_PARALLEL` | 90 | 날개판이 벨트와 나란한 손목 각도 |
| `WRIST_DIVERT` | 50 | 날개판이 벨트 위로 30~45° 비스듬한 손목 각도 |
| `WRIST_MOVE_MS` | 400 | 날개판 회전 시간 (천천히 = 안전) |
| `REST_THUMB` / `REST_FINGER` | 50 / 130 | 손가락 쉬는 자세 (편 손). 손목 고정 장치와 부딪히지 않는 각도로 맞춤. 엄지는 다른 손가락과 방향이 반대 |

### 6.2 `microbit/hand3_signal.ts` (손 3, 신호 손 - 지시)

**역할**
라인 전체 모드의 "기준"입니다. 작업자 수신호(또는 숫자 카드)를 읽어 모드를 정하고, 사람 접근을 감지하고, 정한 모드를 손가락으로 복창합니다(사람 수신호를 그대로 따라 함). 켜지면 일시 정지(3)로 시작하므로 수신호 1·2를 보여 줘야 라인이 출발합니다. 수신호 인식은 aihand-factory 실기 T7 v3(2026-11-21)의 규칙을 옮겨 왔습니다.

**입력 두 가지** (로고를 길게 누르면 바뀜, 화면에 F/N)

| 입력 | WonderCam 기능 | 준비 |
|---|---|---|
| F 수신호 (기본) | 특징 학습 | WonderCam 본체에서 ID 1 OK 사인, 2 V, 3 주먹, 4 손바닥 활짝, 5 빈 배경, (6·7 사람만 서 있음) 학습. 카메라는 작업대를 내려다보게 고정하고 **시연과 같은 높이·거리에서** 학습 |
| N 숫자 카드 | 숫자 인식 | 동봉 카드 1~5, 학습 필요 없음. 카드 5 = 도움 요청 |

**인식 원리** (인식 루프, 약 0.1초마다)
1. 가장 확신하는 번호와 신뢰도를 읽습니다. 신뢰도 0.5(`CONF`) 미만, 빈 배경(ID 5), 사람만 서 있음(ID 6·7)은 "없음"입니다.
2. 같은 번호가 연속 5프레임(`NEED`, 약 0.5초) 보이면 확정합니다. 점검 잠금(4)은 오인식이 잦아 10프레임(`LOCK_NEED`, 약 1초)이 필요합니다.
3. 확정한 번호는 손을 치울 때까지 한 번만 처리합니다. 사람 접근으로 멈춘 뒤, 들고 있던 출발 수신호 때문에 저절로 다시 출발하는 일을 막기 위해서입니다.

**처리 규칙** (`onCommand()`)

| 상황 | 처리 |
|---|---|
| 5 (카드) | 도움 요청 켜기 (점검 잠금 중에도 가능) |
| 점검 잠금 중 | 1~4는 거부 (낮은 경고음 + X 표시). A+B로 해제 |
| 3 주먹, 4 활짝 | 즉시 일시 정지·점검 잠금 (진행 중인 출발 취소) |
| 자동 중 2 V | 즉시 저속 (내려가기) |
| 정지→자동·저속, 저속→자동 (올라가기) | ① 같은 수신호 3초 유지(`HOLD_MS`), 그 동안 프레임 80%(`HOLD_PCT`) 이상 → ② 접근 위험 0일 때만 → ③ 재가동 예고 3초(노랑, 화면 3·2·1, 손가락 3→2→1개, 삐) → 모드 변경 |
| 올라가기 중 사람 접근(위험 1·2), A 버튼, 주먹·활짝 | 바로 취소 (X 표시) |

**접근 감지 원리** (접근 감지 루프, 약 60ms마다)
초음파 거리(mm)를 읽습니다. 0은 측정 실패로 보고 무시합니다.
- **정지 거리**(`STOP_MM`, 기본 200mm) 안: 1번만 감지돼도 즉시 위험 2. 모드가 자동·저속이면 일시 정지로 바꾸고 긴 경고음을 냅니다. 진행 중인 출발도 취소합니다. 사람이 물러나도 스스로 다시 출발하지 않습니다. 수신호 1·2를 다시 보여 줘야 합니다.
- **주의 거리**(`WARN_MM`, 기본 400mm) 안: 연속 3번(`WARN_CONFIRM`) 감지돼야 위험 1로 인정합니다. 스치는 물체 때문에 생기는 오경보를 거르기 위해서입니다. 위험 1에서는 출발(올라가기)을 받지 않습니다.
- 그 밖: 위험 0

위험 단계가 바뀌면 바로 무선으로 알립니다.

**손 동작 루프**
서보는 이 루프 하나만 움직입니다. 여러 루프가 서보를 동시에 건드려 손이 엉키는 것을 막기 위해서입니다.
- 위험 1(주의): 손바닥을 펴고 손목을 좌우로 흔드는 "멈춰" 손짓 + 짧은 경고음
- 재가동 예고 중: 손가락 3→2→1개
- 그 밖: 모드 자세 (1 OK 사인, 2 검지·중지, 3 주먹, 4 활짝 + 손목 170°)
- 같은 자세를 반복해서 보내지 않도록, 마지막으로 취한 자세를 기억합니다(`posedKey`).

**살아 있음 신호**
0.3초마다 `mode`, `help`, `dng`를 다시 보냅니다. 다른 기기들은 이 주기 전송이 끊기는 것으로 손 3이 꺼졌거나 고장 났음을 압니다. 재가동 예고는 손 3 안에서만 진행되고, 다른 기기에는 예고가 끝나 모드가 바뀐 뒤에 전달됩니다.

**버튼·터치**

| 입력 | 동작 |
|---|---|
| A | 즉시 일시 정지 (수신호 없이 급히 멈출 때, 진행 중인 출발 취소. 잠금 중에는 무시) |
| B | 도움 요청 끄기 |
| A+B | 점검 잠금 해제 → 일시 정지(3). 출발은 다시 수신호 1·2로 |
| 로고 터치 | 도움 요청 켜기 |
| 로고 길게 누르기 | 입력 바꾸기 (F 수신호 ↔ N 숫자 카드) |

> **주의**: WonderCam이 연결되어 있지 않으면 시작할 때 화면에 "E"를 띄우며 계속 기다립니다 (WonderCam 확장의 동작). 카메라 연결부터 확인하세요.
>
> **T7 측정 결과 (2026-11-21, 수신호 v1 기준)**: 확정 맞힘 81%, 다른 번호로 잘못 확정 5회/26회. 틀릴 때도 신뢰도가 0.8~0.9라 신뢰도 기준만으로는 거르지 못합니다. 학습 때보다 멀어지면 인식이 줄어드므로 카메라 높이·손 위치를 고정하세요. 올라가기에 3초 유지 + 예고를 둔 것도 이 때문입니다.

### 6.3 `microbit/hand4_display.ts` (손 4, 신호 손 - 원격 표시)

**역할**
라인에서 떨어진 관리자 쪽에 두고, 무선으로 받은 상태를 손가락·LED·소리로 보여 줍니다. 센서 입력은 없고 무선만 받습니다.

**표시 우선순위** (손 동작 루프)
1. **도움 요청**: 파랑 LED, 손가락을 하나씩 굽혔다 펴며 흔들기, 2초마다 두 음 호출음, 화면 "H"
2. **위험 1**: "멈춰" 손짓 + 경고음, 화면 "!"
3. **평소**: 모드 자세 (손 3과 같은 자세), 화면에 모드 번호

위험 2(정지 거리 진입)가 오면 긴 경고음을 내고 화면에 X를 표시합니다.

**신호 끊김**
`mode`가 2초 동안 오지 않으면 보라색 LED, 화면 "?", 낮은 경고음을 내고 주먹 자세로 바꿉니다.

### 6.4 `microbit/gateway_bridge.ts` (게이트웨이)

**역할**
확장보드 없이 노트북 USB에 꽂아 두는 micro:bit입니다. 세 가지를 중계합니다.
1. 무선 모드 → 아두이노 핀 (벨트 제어)
2. 노트북 판정 → 무선 (손 1·2)
3. 무선 상태 변화 → 노트북 시리얼 (대시보드 기록용)

**아두이노로 모드 넘기기** (`writeModePins()`)
- `mode`를 받으면 [5.5](#55-게이트웨이--아두이노-핀-신호)의 표대로 P0·P1을 씁니다.
- 손 3 신호가 1.5초 동안 끊기면 핀을 STOP(00)으로 바꾸고, P2 살아 있음 토글을 멈춥니다. 아두이노는 토글이 멈춘 것을 보고 벨트를 잠급니다.
- 신호가 살아 있는 동안에는 P2를 0.1초마다 0↔1로 바꿉니다.

**판정 보내기** (`sendJudgement()`)
노트북에서 `J0`~`J4` 한 줄을 받으면 순번을 1 올리고, 값 = 순번 × 10 + 판정을 `jdg`로 3번 보낸 뒤 `ACK,순번,판정`을 돌려줍니다.
순번은 1~999를 돕니다. 시작 순번은 무작위로 정합니다. 게이트웨이를 다시 켰을 때 첫 판정의 순번이 손이 기억하는 직전 순번과 우연히 같아서 중복으로 버려지는 일을 막기 위해서입니다.

**시험용 버튼** (노트북 없이 손 1·2 시험)

| 버튼 | 보내는 판정 |
|---|---|
| A | 4 유색 (손 1 분기) |
| B | 2 내용물 (손 2 분기) |
| A+B | 1 적합 (둘 다 통과) |

### 6.5 `arduino/conveyor/conveyor.ino` (컨베이어)

**역할**
게이트웨이가 보내는 모드대로 스텝모터 속도를 바꾸고, 안전 조건이 깨지면 벨트를 멈춘 채 잠급니다.

**핀**

| 핀 | 연결 | 방향 |
|---|---|---|
| D3 | TB6600 PUL (스텝 펄스) | 출력 |
| D4 | TB6600 DIR (방향) | 출력 |
| D5 | TB6600 ENA (드라이버 사용) | 출력 |
| D6 | 게이트웨이 P0 (모드 비트 0) | 입력 |
| D7 | 게이트웨이 P1 (모드 비트 1) | 입력 |
| D8 | 게이트웨이 P2 (살아 있음 신호) | 입력 |
| D10 | 리셋 버튼 (GND와 연결, 누르면 LOW) | 입력 |
| D11 | (선택) 비상정지 보조 접점 감지 | 입력 |
| D12 | (선택) 릴레이 (드라이버 전원 차단) | 출력 |

**잠김(Latch) 상태**
다음 경우에는 벨트를 즉시 멈추고 "잠김"이 됩니다.

| 잠김 이유 | 조건 |
|---|---|
| `POWERON` | 전원을 켰을 때 (켜자마자 돌지 않게) |
| `HEARTBEAT_LOST` | 살아 있음 신호(D8)가 0.6초 동안 바뀌지 않음 |
| `ESTOP` | 비상정지 감지 배선을 했고 버튼이 눌림 |

잠김은 **리셋 버튼(D10)을 눌러야만** 풀립니다. 이때 살아 있음 신호가 없거나 비상정지가 눌린 상태면 리셋을 거부하고 이유를 시리얼에 출력합니다. 릴레이를 쓰도록 설정하면 잠김 동안 드라이버 전원도 끊습니다.

**속도 결정** (`updateTarget()` → `rampSpeed()` → `stepMotor()`)
1. 목표 속도: NORMAL → `NORMAL_SPS`, SLOW → `SLOW_SPS`, STOP·LOCK·잠김 → 0 (스텝/초 단위)
2. 목표가 0이면 감속 없이 **즉시** 멈춥니다 (사람 접근 정지가 늦어지지 않게).
3. 속도를 올릴 때와 보통→저속으로 내릴 때는 5ms마다 `ACCEL_SPS2`만큼 천천히 바꿉니다. 스텝모터가 급가속으로 헛도는(탈조) 것을 막기 위해서입니다.
4. 현재 속도에 맞는 간격(1,000,000 ÷ 속도 μs)마다 PUL 핀에 10μs 펄스를 냅니다. `delay()`를 쓰지 않는 방식이라 그동안에도 버튼·신호 확인이 계속 돕니다.

**시리얼 명령** (115200bps, 줄 끝 "새 줄")

| 명령 | 동작 |
|---|---|
| `?` | 현재 상태 출력 (모드, 잠김 이유, 현재·목표 속도 등) |
| `N800` | 자동 속도를 800 스텝/초로 |
| `S300` | 저속 속도를 300 스텝/초로 |
| `A1500` | 가속도를 1500 스텝/초²로 |
| `D` | 회전 방향 반대로 |
| `T` | 시험 모드 켜기/끄기. 켜면 micro:bit 입력과 살아 있음 신호를 무시하고 시리얼로 모드를 정합니다. 끄면 다시 `POWERON` 잠김이 됩니다. |
| `1`~`4` | (시험 모드에서만) 모드 지정. 1 자동, 2 저속, 3 정지, 4 잠금 |
| `R` | (시험 모드에서만) 잠김 해제 |

시리얼로 바꾼 값은 전원을 끄면 사라집니다. 정한 값은 코드 위쪽 상수에 적어 두세요.

**주요 설정값** (파일 위쪽 "설정" 부분)

| 상수 | 의미 |
|---|---|
| `NORMAL_SPS`, `SLOW_SPS` | 속도 (TB6600 마이크로스텝 설정에 따라 실제 속도가 달라짐) |
| `ACCEL_SPS2` | 가속도 |
| `DIR_FORWARD` | 회전 방향 |
| `USE_ESTOP_SENSE` | 비상정지 보조 접점을 D11에 배선했으면 `true` |
| `USE_RELAY` / `RELAY_ACTIVE_HIGH` | 릴레이 사용 여부와 동작 레벨 |
| `ENA_ENABLE_LEVEL` | 드라이버를 켜는 ENA 레벨 (TB6600은 보통 `LOW`) |

## 7. 안전 설계 요약

**멈추는 경로가 여러 개입니다.**
1. 사람 접근(정지 거리) → 손 3이 일시 정지로 바꿈 → 모든 기기·벨트 정지
2. 손 3이 꺼지거나 고장 → 살아 있음 신호 끊김 → 손들과 벨트가 스스로 정지
3. 게이트웨이 선이 빠짐 → 아두이노가 LOCK + 신호 끊김으로 읽고 정지·잠김
4. 비상정지 버튼 → 드라이버 전원을 직접 끊음 (프로그램과 무관하게 배선)

**멈춘 뒤 저절로 다시 돌지 않습니다.**
- 사람 접근 정지 뒤에는 수신호 1·2를 "새로" 보여 주고 3초 유지 + 3초 예고를 거쳐야 출발합니다.
- 아두이노 잠김은 리셋 버튼으로만 풀립니다.

**그 밖**
- 정지는 감속 없이 즉시, 출발은 천천히 합니다.
- 노트북은 정지 경로에 없습니다. 판정과 기록만 맡습니다.

> 교육용 시제품이며 산업 안전 인증 장비가 아닙니다.

## 8. 업로드 방법과 배선

### 8.1 micro:bit (손 1~4, 게이트웨이)

1. https://makecode.microbit.org 접속 → 새 프로젝트
2. 톱니바퀴 → 확장(Extensions) → 아래 주소를 검색해 추가
   - 손 1~4: `https://github.com/Hiwonder/StartbitV2`
   - 손 3만 추가로: `https://github.com/Hiwonder/WonderCam` (수신호를 쓰려면 WonderCam 본체에서 특징 학습 ID 1~5를 먼저 학습)
   - 게이트웨이: 추가할 확장 없음
3. 위쪽 **JavaScript** 탭을 열고, 기존 내용을 지운 뒤 해당 `.ts` 파일 내용 전체를 붙여넣습니다. 손 1·2는 붙여넣은 뒤 `HAND_ID` 값을 1 또는 2로 바꿉니다.
4. **다운로드**를 눌러 받은 `.hex` 파일을 `MICROBIT` 드라이브에 복사합니다. Chrome·Edge에서는 WebUSB 페어링으로 바로 업로드할 수도 있습니다.
5. 모든 기기의 `RADIO_GROUP` 값이 같은지 확인합니다. 같은 공간의 다른 팀과 겹치면 모두 같은 다른 값으로 바꿉니다.

> - 블록 탭으로 바꾸면 일부가 회색 블록으로 보일 수 있습니다. JavaScript 탭에서 수정하세요.
> - 로봇 손은 7.5V 어댑터를 연결해야 서보가 움직입니다.

### 8.2 아두이노

Arduino IDE에서 `conveyor/conveyor.ino`를 열고 보드를 **Arduino Uno**로 골라 업로드합니다. 추가 라이브러리는 필요 없습니다.

명령줄을 쓴다면:

```
arduino-cli compile --fqbn arduino:avr:uno conveyor
arduino-cli upload  --fqbn arduino:avr:uno -p COM포트 conveyor
```

### 8.3 배선

**게이트웨이 micro:bit → 아두이노** (악어클립 또는 엣지 커넥터)

| micro:bit | 아두이노 |
|---|---|
| P0 | D6 |
| P1 | D7 |
| P2 | D8 |
| GND | GND (**반드시 연결**) |

**아두이노 → TB6600** (공통 음극 방식)

| 아두이노 | TB6600 |
|---|---|
| D3 | PUL+ |
| D4 | DIR+ |
| D5 | ENA+ |
| GND | PUL-, DIR-, ENA- |

- TB6600 전원(VCC/GND) ← 24V 전원. 비상정지 버튼을 이 선에 직렬로 넣습니다.
- TB6600 A+/A-/B+/B- ← 스텝모터

**버튼**
- 리셋 버튼: D10 ↔ GND
- (선택) 비상정지 보조 접점: D11 ↔ GND (평소 닫힘), 코드에서 `USE_ESTOP_SENSE = true`
- (선택) 릴레이: 모듈 IN → D12, 코드에서 `USE_RELAY = true`

> **전압 주의**: micro:bit는 3.3V, 아두이노 우노는 5V입니다. 이 구성은 micro:bit가 아두이노로 출력만 하므로 그대로 연결해도 됩니다 (3.3V는 우노에서 HIGH로 읽힘). 반대로 아두이노 출력을 micro:bit 핀에 직접 넣으면 안 됩니다.

## 9. 보정

코드 안의 ★ 표시 값은 실물에서 확인하지 않은 임시값입니다.

1. **손 1·2 날개판**
   - 먼저 손목을 돌렸을 때 날개판이 벨트 위에서 수평으로 도는지 확인합니다.
   - `WRIST_PARALLEL`: 날개판이 벨트 가장자리와 나란해지는 각도
   - `WRIST_DIVERT`: 날개판이 벨트를 30~45°로 가로막는 각도. 날개판 끝이 벨트 반대쪽 가장자리에 닿아야 병이 빠져나갑니다.
   - `REST_*`: 손가락이 손목 고정 장치와 부딪히지 않는 쉬는 자세
   - 병이 날개판을 밀어도 장치가 손목에서 돌거나 흔들리지 않는지 확인합니다.
   - 각도를 맞출 때는 일시 정지 상태에서 A(비스듬히)·B(나란히) 버튼으로 두 위치를 번갈아 확인할 수 있습니다.
2. **손 3 접근 거리**
   - 초음파 앞으로 손을 천천히 가져가며 `WARN_MM` / `STOP_MM`을 정합니다.
   - 초음파는 벨트 쪽 접근 경로를 향하게 둡니다. 수신호·카드를 보여 주는 위치가 초음파 정면이면 손을 내밀 때마다 정지가 걸립니다.
3. **손 3 수신호**
   - 카메라를 작업대 위에 고정하고 시연과 같은 높이·거리에서 ID 1~5(필요하면 6·7)를 학습합니다.
   - 로고를 길게 눌러 N(숫자 카드)으로 바꾸면 학습 없이 카드로도 시험할 수 있습니다.
4. **벨트 속도**
   - 아두이노 시리얼 모니터에서 `T` → `R` → `1` 순서로 시험 모드 출발
   - `N`, `S` 명령으로 속도를 바꿔 보며 정하고, 출발 때 모터가 떨면 `A` 값을 낮춥니다.
   - 정한 값을 코드의 `NORMAL_SPS` / `SLOW_SPS`에 적어 다시 업로드합니다.

## 10. 시험 순서

재료가 다 갖춰지지 않아도 앞 단계부터 따로 시험할 수 있습니다.

1. **손 단독**: 손 1에 업로드 → A로 비스듬히, B로 나란히 손목이 도는지 확인. 손 3이 없으니 "?"가 뜨는 것이 정상입니다.
2. **손 3 + 손 4**: 수신호 1~4(1·2는 3초 유지 → 예고 3초)와 카드 5(로고 길게 눌러 N)를 보여 주고 손 3이 복창하고 손 4가 따라 하는지 확인. 손 3 전원을 끄면 2초 안에 손 4에 "?"가 떠야 합니다.
3. **게이트웨이 + 손 1·2 (+ 손 3)**: 손 3에 수신호 1(OK 사인) → 게이트웨이 버튼
   - A(유색) → 손 1이 비스듬히
   - B(내용물) → 손 2가 비스듬히
   - A+B(적합) → 둘 다 나란히
4. **아두이노 단독**: 시리얼 시험 모드로 속도·방향 확인
5. **전체**: 게이트웨이 핀 연결 → 리셋 버튼 → OK 사인 3초(예고 뒤 벨트 출발) → V(즉시 저속) → 주먹(정지) → 손 3 끄기(벨트 정지·잠김) → 손 3 켜고 리셋 → OK 사인(재출발). 노트북에서 `J0`~`J4`를 보내 분기까지 확인합니다.

## 11. 알려진 한계와 미확정 사항

- **검증 상태**: 아두이노 코드는 컴파일까지 확인했습니다 (Uno 기준 프로그램 공간 약 25%). micro:bit 코드는 Hiwonder 확장 소스와 대조해 작성했지만, 실물 업로드와 동작 시험은 아직 하지 않았습니다. 손 3의 수신호 인식 규칙은 T7 프로그램으로 실물 시험했지만(확정 81%), 이 파일로 합친 뒤에는 아직 시험하지 않았습니다.
- **병 투입 간격**: 날개판은 판정을 받는 즉시 움직이고 다음 판정이 올 때까지 그 자세를 유지합니다. 따라서 검사 자리와 손 2 사이에는 병이 한 개만 있어야 합니다. 병이 더 촘촘하게 들어오려면 병별로 도착 시각을 계산하는 방식이 필요합니다.
- **범위 밖**: YOLO 판정 프로그램과 대시보드는 이 폴더에 없습니다. [5.4](#54-노트북--게이트웨이-시리얼-usb-115200bps-줄-단위)의 형식만 맞추면 연결됩니다.
- **임시로 정한 것**: 원래 팀 역할표에 없어서 임시로 정했으며, 팀 결정에 따라 바뀔 수 있습니다.
  - 게이트웨이 micro:bit 추가
  - 주의 거리에서는 경고만(출발은 막음), 정지 거리에서는 일시 정지 + 수신호로 재출발
  - 손 3 버튼 배정 (A 정지, B 도움 끄기, 로고 도움 켜기, 로고 길게 F/N 전환, A+B 잠금 해제)
  - 점검 잠금 해제는 손 3의 A+B
