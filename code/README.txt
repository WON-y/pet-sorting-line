----------------------------------------------------------------------
 1. 무엇을 만드는가
----------------------------------------------------------------------

컨베이어 벨트 위로 지나가는 페트병을 카메라(노트북 YOLO)가 판정하고,
벨트 옆에 놓인 로봇 손이 "날개판"을 돌려 병을 알맞은 쪽으로 흘려보내는
탁상용 선별 셀이다.

 - 투명하고 깨끗한 병      → 벨트 끝까지 그대로 통과 (투명 페트 통)
 - 유색·불투명 병          → 손 1이 날개판으로 옆 슈트로 분기
 - 내용물 남음·라벨 있음 병 → 손 2가 날개판으로 부적합 통으로 분기

로봇 손에는 팔이 없어서 병을 집어 옮길 수 없다. 그래서 손목 부분에
날개판을 장치로 고정해 두고, 손목을 돌려 날개판을 벨트 위에 비스듬히
놓는다. 병은 벨트의 흐름에 밀려 날개판을 따라 옆으로 빠진다
(스윙 암 분기 방식). 손가락은 이 동작에 쓰지 않는다.

작업자는 숫자 카드(1~5)를 손 3에게 보여 주는 것으로 라인 전체의 모드
(자동, 저속, 일시 정지, 점검 잠금, 도움 요청)를 바꾼다. 사람이 벨트에
가까이 다가오면 라인은 스스로 멈춘다.


----------------------------------------------------------------------
 2. 사용하는 하드웨어
----------------------------------------------------------------------

 - 로봇 손 4대: Hiwonder AiHand
     · micro:bit V2 + Hiwonder 확장보드 (보드 위 MCU가 서보를 구동)
     · 서보 6개: 1~5번 = 엄지~새끼손가락, 6번 = 손목 회전
     · 전원 7.5V 어댑터 필요 (USB 전원만으로는 서보가 움직이지 않음)
     · 초음파 센서 (I2C, 거리 + RGB LED 2개)
     · 손 3에만 WonderCam AI 카메라 (I2C, 숫자 인식 기능 사용)
 - 게이트웨이용 micro:bit V2 1개 (확장보드 없이 단독 사용)
 - 아두이노 우노 (호환 보드 가능)
 - TB6600 스텝모터 드라이버 + 스텝모터 컨베이어 + 24V 전원
 - 리셋 버튼, 비상정지 버튼, (선택) 릴레이 모듈
 - 노트북: YOLO 판정 프로그램 실행 (이 폴더에는 없음)

 3. 폴더 구조
----------------------------------------------------------------------

 code/
 ├─ README.md                  이 문서의 마크다운판 (깃허브 첫 화면 표시용)
 ├─ README.txt                 이 문서
 ├─ CLAUDE.md                  인수인계 문서 (결정 사항, 검증 상태, 수정 규칙)
 ├─ microbit/                  micro:bit 프로그램 (MakeCode JavaScript)
 │   ├─ hand12_sorter.ts       손 1, 손 2 공용 - 날개판 분기
 │   ├─ hand3_signal.ts        손 3 - 숫자 카드 지시, 접근 감지 (모드의 기준)
 │   ├─ hand4_display.ts       손 4 - 원격 상태 표시
 │   └─ gateway_bridge.ts      게이트웨이 - 노트북·무선·아두이노 사이 중계
 └─ arduino/
     └─ conveyor/
         └─ conveyor.ino       아두이노 - 컨베이어 속도 제어, 안전 정지

 .ts 파일은 MakeCode(makecode.microbit.org)의 JavaScript 편집기에
 붙여넣어 쓰는 TypeScript 코드다. 파일 하나가 micro:bit 한 대의
 프로그램 전체다.

 4. 전체 동작 구조
----------------------------------------------------------------------

  [노트북 YOLO]
       │ USB 시리얼 "J0"~"J4" (병 하나당 한 줄)
       ▼
  [게이트웨이 micro:bit] ──핀 P0·P1·P2──▶ [아두이노] ──▶ [TB6600] ──▶ 벨트
       │   ▲
  무선 │   │ 무선 "mode" "help" "dng" (0.3초마다)
 "jdg" │   │
       ▼   │
  [손 1] [손 2]      [손 3: 카드·초음파] ───무선───▶ [손 4: 원격 표시]
   날개판 분기         모드의 기준                       상태 표시

 신호는 세 갈래로 흐른다.

 (1) 모드 신호 (누가 무엇을 할지)
     손 3이 카드를 읽어 모드를 정하고, 0.3초마다 무선으로 모두에게 보낸다.
     손 1·2·4와 게이트웨이는 이 신호를 받아 각자 동작을 바꾼다.
     게이트웨이는 모드를 2비트 핀 신호로 바꿔 아두이노에 넘긴다.

 (2) 판정 신호 (병이 어디로 갈지)
     노트북 YOLO → USB → 게이트웨이 → 무선 → 손 1·2.
     손 1·2는 판정에 따라 날개판을 비스듬히 놓거나 나란히 접는다.

 (3) 살아 있음 신호 (멈춰야 하는지)
     손 3의 0.3초 주기 모드 전송이 곧 "살아 있음" 신호다.
     이 신호가 끊기면 손 1·2·4는 스스로 멈추고, 게이트웨이는 아두이노로
     가는 핀 토글을 멈춘다. 아두이노는 토글이 끊기면 벨트를 세우고 잠근다.
     노트북은 이 경로에 끼지 않는다. 노트북이 꺼져도 정지는 동작한다.


----------------------------------------------------------------------
 5. 공통 약속
----------------------------------------------------------------------

 5.1 모드 번호 (숫자 카드 번호와 같음)

  1 자동      벨트 보통 속도 / LED 초록 / 손 3·4 활짝 폄 / 손 1·2 판정대로 분기
  2 저속      벨트 느리게   / LED 노랑 / 손 3·4 검지·중지만 폄 / 손 1·2 분기
  3 일시 정지 벨트 멈춤     / LED 빨강 / 손 3·4 주먹 / 손 1·2 그 자리 멈춤
  4 점검 잠금 벨트 멈춤, 카드로 재가동 불가 / LED 빨강 깜빡임
              / 손 3·4 주먹 + 손목 돌림 / 손 1·2 날개판 접고 멈춤
  5 도움 요청 모드와 별개로 켜지는 표시. 벨트·작업 손은 그대로,
              손 4만 파랑 LED + 호출음 + 손가락 흔들기

  ※ 코드 안에서 "mode"는 1~4만 쓰고, 도움 요청은 "help"(0/1)로 따로 보낸다.
    도움 요청 중에도 원래 모드(자동/저속 등)가 그대로 유지되게 하기 위해서다.

 5.2 판정 번호

  0 재검사 (YOLO가 확신하지 못함)
  1 투명 적합
  2 내용물 남음
  3 라벨 있음
  4 유색·불투명

 5.3 무선(micro:bit radio) 메시지

  모든 기기는 같은 무선 그룹(RADIO_GROUP, 기본 73)을 써야 한다.
  메시지는 radio.sendValue(이름, 숫자) 형식이다.

  이름    보내는 쪽    값                          의미
  "mode"  손 3         1~4                         현재 모드 (0.3초마다 반복)
  "help"  손 3         0 / 1                       도움 요청 꺼짐 / 켜짐
  "dng"   손 3         0 / 1 / 2                   접근 위험: 정상 / 주의 / 정지 거리
  "jdg"   게이트웨이   순번 × 10 + 판정번호        병 판정 (예: 순번 57, 판정 4 → 574)

  "jdg"는 무선 손실에 대비해 같은 값을 20ms 간격으로 3번 보낸다.
  받는 쪽은 순번(값 ÷ 10)이 직전과 같으면 무시해서 한 번만 처리한다.

 5.4 노트북 ↔ 게이트웨이 시리얼 (USB, 115200bps, 줄 단위)

  노트북 → 게이트웨이:  J0, J1, J2, J3, J4   (J + 판정번호)
  게이트웨이 → 노트북:
    ACK,순번,판정     판정을 무선으로 보냈음
    MODE,n            모드가 n으로 바뀜
    HELP,0 / HELP,1   도움 요청 꺼짐 / 켜짐
    DNG,0 / 1 / 2     접근 위험 단계가 바뀜
    LINK,OK / LOST    손 3 신호를 받기 시작함 / 끊김
    ERR,받은내용      형식이 틀린 줄

 5.5 게이트웨이 → 아두이노 핀 신호

  P0 = 모드 비트 0, P1 = 모드 비트 1, P2 = 살아 있음 토글(0.1초마다 0↔1)

  모드          P1 P0    아두이노가 읽는 값
  자동           0  1    NORMAL (보통 속도)
  저속           1  0    SLOW   (느리게)
  일시 정지      0  0    STOP
  점검 잠금      1  1    LOCK   (멈춤)

  아두이노는 이 핀들을 내부 풀업(INPUT_PULLUP)으로 읽는다. 선이 빠지면
  두 비트가 모두 1이 되어 LOCK(멈춤)으로 읽힌다. 살아 있음 토글도
  멈추므로 아두이노는 잠김 상태가 된다.

 6. 파일별 상세 설명
----------------------------------------------------------------------

 ■ 6.1 microbit/hand12_sorter.ts  (손 1, 손 2 공용)

 [역할]
  손목 부분에 고정된 날개판을, 판정에 따라 손목(6번 서보)을 돌려
  "비스듬히(분기)" 또는 "나란히(통과)"로 놓는다.
  손가락은 시작할 때 쉬는 자세로 한 번 맞춘 뒤 움직이지 않는다.
  파일 맨 위 HAND_ID를 1 또는 2로 바꿔서 손 1과 손 2에 각각 올린다.

 [분기 규칙]  shouldDivert()
  손 1: 판정 4(유색·불투명)이면 분기
  손 2: 판정 0(재검사), 2(내용물), 3(라벨)이면 분기
  나머지 판정에는 날개판을 나란히 둔다.

   판정            손 1 날개판   손 2 날개판   병이 가는 곳
   1 투명 적합     나란히        나란히        벨트 끝 (투명 페트 통)
   4 유색·불투명   비스듬히      나란히        손 1 쪽 슈트
   0, 2, 3         나란히        비스듬히      손 2 쪽 부적합 통

 [움직여도 되는 조건]  canMove()
  ① 손 3 신호가 살아 있고, ② 모드가 자동·저속일 때만 날개판을 움직인다. 하나라도 아니면 판정을 "대기 판정(pendingTarget)"으로
  기억해 두었다가, 조건이 다시 맞으면 그때 적용한다.

 [모드별 동작]  onModeChange()
  자동·저속  : 대기 판정이 있으면 적용
  일시 정지  : 아무것도 하지 않음 (그 자리 멈춤). 이후 받은 판정은 대기
  점검 잠금  : 날개판을 나란히 접고, 대기 판정을 버림. 판정을 받아도 무시

 [신호 끊김]
  "mode" 메시지를 받을 때마다 시각을 기록한다. 2초(LINK_TIMEOUT_MS) 동안
  오지 않으면 신호 끊김으로 보고 움직임을 멈춘다. 이때 LED는 보라색,
  화면에는 "?"가 뜬다. 신호가 돌아오면 대기 판정을 적용하고 이어서 동작한다.

 [버튼]
  날개판 각도를 맞출 때 쓰는 버튼이다.
  A: 손목을 비스듬히(분기) 위치로 돌림 (화면에 ↗)
  B: 손목을 나란히(통과) 위치로 돌림 (화면에 ↑)
  벨트가 도는 중(자동·저속)에는 두 버튼 모두 무시된다. 동작 중에 날개판이
  엉뚱한 위치로 가는 것을 막기 위해서다. 일시 정지 중에 A로 시험했다면,
  다시 출발하기 전에 B로 나란히 위치에 돌려 둔다.

 [화면·LED]
  시작 시 손목을 나란히 위치로 돌리고 HAND_ID를 표시한다.
  판정을 받으면 판정 번호를 표시한다 (날개판을 먼저 움직인 뒤 표시).
  LED 색: 초록 자동 / 노랑 저속 / 빨강 정지 / 빨강 깜빡임 잠금 / 보라 신호 끊김
  LED는 초음파 센서의 RGB LED와 확장보드 RGB LED에 같이 낸다.

 [주요 설정값]
  WRIST_PARALLEL  날개판이 벨트와 나란한 손목 각도 (기본 90)
  WRIST_DIVERT    날개판이 벨트 위로 30~45° 비스듬한 손목 각도 (기본 50)
  WRIST_MOVE_MS   날개판 회전 시간 (기본 400ms, 천천히 = 안전)
  REST_THUMB / REST_FINGER  손가락 쉬는 자세 (기본 50 / 130 = 편 손).
                            손목 고정 장치와 부딪히지 않는 각도로 맞춘다.
                            엄지는 다른 손가락과 방향이 반대다.

 ■ 6.2 microbit/hand3_signal.ts  (손 3, 신호 손 - 지시)

 [역할]
  라인 전체 모드의 "기준"이다. 숫자 카드를 읽어 모드를 정하고, 사람 접근을
  감지하고, 정한 모드를 손가락으로 복창한다. 켜지면 일시 정지(3)로 시작하므로
  카드 1·2를 보여 줘야 라인이 출발한다.

 [카드 인식 원리]  카드 인식 루프 (약 50ms마다)
  WonderCam을 숫자 인식 기능으로 두고, 가장 확신하는 숫자와 신뢰도를 읽는다.
   1) 숫자가 1~5이고 신뢰도가 0.6(CARD_CONF) 이상이면 "보임"으로 센다.
   2) 같은 숫자가 연속 3번(CARD_FRAMES) 보이면 확정한다. 순간 오인식을 막는다.
   3) 확정한 뒤에는 카드가 연속 8번(REARM_FRAMES) 안 보여야 다음 카드를 받는다.
      카드를 계속 들고 있어도 한 번만 처리하기 위해서다. 예를 들어 사람 접근으로
      멈춘 뒤, 들고 있던 출발 카드 때문에 저절로 다시 출발하는 일을 막는다.

 [카드 처리 규칙]  handleCard()
  카드 5           : 도움 요청 켜기 (점검 잠금 중에도 가능)
  점검 잠금 중     : 카드 1~4는 거부 (낮은 경고음 + X 표시)
  정지 거리 안에 사람이 있을 때 : 카드 1·2(출발)는 거부
  그 밖            : 도움 요청을 끄고 카드 번호대로 모드 변경 + 확인음

 [접근 감지 원리]  접근 감지 루프 (약 60ms마다)
  초음파 거리(mm)를 읽는다. 0은 측정 실패로 보고 무시한다.
  - 정지 거리(STOP_MM, 기본 200mm) 안: 1번만 감지돼도 즉시 위험 2.
    모드가 자동·저속이면 일시 정지로 바꾸고 긴 경고음을 낸다.
    사람이 물러나도 스스로 다시 출발하지 않는다. 카드 1·2를 다시 보여 줘야 한다.
  - 주의 거리(WARN_MM, 기본 400mm) 안: 연속 3번(WARN_CONFIRM) 감지돼야
    위험 1로 인정한다. 스치는 물체 때문에 생기는 오경보를 거르기 위해서다.
  - 그 밖: 위험 0
  위험 단계가 바뀌면 바로 무선으로 알린다.

 [손 동작 루프]
  서보는 이 루프 하나만 움직인다. 여러 루프가 서보를 동시에 건드려
  손이 엉키는 것을 막기 위해서다.
  - 위험 1(주의): 손바닥을 펴고 손목을 좌우로 흔드는 "멈춰" 손짓 + 짧은 경고음
  - 그 밖: 모드 자세 (1 활짝, 2 검지·중지, 3 주먹, 4 주먹 + 손목 170°)
  같은 자세를 반복해서 보내지 않도록, 마지막으로 취한 자세를 기억한다(posedKey).

 [살아 있음 신호]
  0.3초마다 "mode", "help", "dng"를 다시 보낸다. 다른 기기들은 이 주기 전송이
  끊기는 것으로 손 3이 꺼졌거나 고장 났음을 안다.

 [버튼·터치]
  A        : 즉시 일시 정지 (카드 없이 급히 멈출 때. 잠금 중에는 무시)
  B        : 도움 요청 끄기
  A+B      : 점검 잠금 해제 → 일시 정지(3). 출발은 다시 카드 1·2로
  로고 터치 : 도움 요청 켜기

 [주의]
  WonderCam이 연결되어 있지 않으면 시작할 때 화면에 "E"를 띄우며 계속
  기다린다 (WonderCam 확장의 동작). 카메라 연결부터 확인할 것.

 ■ 6.3 microbit/hand4_display.ts  (손 4, 신호 손 - 원격 표시)

 [역할]
  라인에서 떨어진 관리자 쪽에 두고, 무선으로 받은 상태를 손가락·LED·소리로
  보여 준다. 센서 입력은 없고 무선만 받는다.

 [표시 우선순위]  손 동작 루프
  1) 도움 요청 : 파랑 LED, 손가락을 하나씩 굽혔다 펴며 흔들기,
                 2초마다 두 음 호출음, 화면 "H"
  2) 위험 1    : "멈춰" 손짓 + 경고음, 화면 "!"
  3) 평소      : 모드 자세 (손 3과 같은 자세), 화면에 모드 번호
  위험 2(정지 거리 진입)가 오면 긴 경고음을 내고 화면에 X를 표시한다.

 [신호 끊김]
  "mode"가 2초 동안 오지 않으면 보라색 LED, 화면 "?", 낮은 경고음을 내고
  주먹 자세로 바꾼다.

 ■ 6.4 microbit/gateway_bridge.ts  (게이트웨이)

 [역할]
  확장보드 없이 노트북 USB에 꽂아 두는 micro:bit다. 세 가지를 중계한다.
   ① 무선 모드 → 아두이노 핀 (벨트 제어)
   ② 노트북 판정 → 무선 (손 1·2)
   ③ 무선 상태 변화 → 노트북 시리얼 (대시보드 기록용)

 [아두이노로 모드 넘기기]  writeModePins()
  "mode"를 받으면 5.5의 표대로 P0·P1을 쓴다.
  손 3 신호가 1.5초 동안 끊기면 핀을 STOP(00)으로 바꾸고,
  P2 살아 있음 토글을 멈춘다. 아두이노는 토글이 멈춘 것을 보고 벨트를 잠근다.
  신호가 살아 있는 동안에는 P2를 0.1초마다 0↔1로 바꾼다.

 [판정 보내기]  sendJudgement()
  노트북에서 "J0"~"J4" 한 줄을 받으면 순번을 1 올리고,
  값 = 순번 × 10 + 판정을 "jdg"로 3번 보낸 뒤 "ACK,순번,판정"을 돌려준다.
  순번은 1~999를 돈다. 시작 순번은 무작위로 정한다. 게이트웨이를 다시
  켰을 때 첫 판정의 순번이 손이 기억하는 직전 순번과 우연히 같아서
  중복으로 버려지는 일을 막기 위해서다.

 [시험용 버튼]  (노트북 없이 손 1·2 시험)
  A = 판정 4(유색, 손 1 분기), B = 판정 2(내용물, 손 2 분기), A+B = 판정 1(적합)

 ■ 6.5 arduino/conveyor/conveyor.ino  (컨베이어)

 [역할]
  게이트웨이가 보내는 모드대로 스텝모터 속도를 바꾸고, 안전 조건이
  깨지면 벨트를 멈춘 채 잠근다.

 [핀]
  D3 PUL(스텝 펄스), D4 DIR(방향), D5 ENA(드라이버 사용)  → TB6600
  D6 모드 비트 0, D7 모드 비트 1, D8 살아 있음 신호       ← 게이트웨이
  D10 리셋 버튼 (GND와 연결, 누르면 LOW)
  D11 (선택) 비상정지 보조 접점 감지
  D12 (선택) 릴레이 (드라이버 전원 차단)

 [잠김(Latch) 상태]
  다음 경우에는 벨트를 즉시 멈추고 "잠김"이 된다.
   - POWERON        : 전원을 켰을 때 (켜자마자 돌지 않게)
   - HEARTBEAT_LOST : 살아 있음 신호(D8)가 0.6초 동안 바뀌지 않음
   - ESTOP          : 비상정지 감지 배선을 했고 버튼이 눌림
  잠김은 리셋 버튼(D10)을 눌러야만 풀린다. 이때 살아 있음 신호가 없거나
  비상정지가 눌린 상태면 리셋을 거부하고 이유를 시리얼에 출력한다.
  릴레이를 쓰도록 설정하면 잠김 동안 드라이버 전원도 끊는다.

 [속도 결정]  updateTarget() → rampSpeed() → stepMotor()
  1) 목표 속도: NORMAL → NORMAL_SPS, SLOW → SLOW_SPS,
     STOP·LOCK·잠김 → 0 (스텝/초 단위)
  2) 목표가 0이면 감속 없이 즉시 멈춘다 (사람 접근 정지가 늦어지지 않게).
  3) 속도를 올릴 때와 보통→저속으로 내릴 때는 5ms마다
     ACCEL_SPS2만큼 천천히 바꾼다. 스텝모터가 급가속으로 헛도는(탈조)
     것을 막기 위해서다.
  4) 현재 속도에 맞는 간격(1,000,000 ÷ 속도 μs)마다 PUL 핀에 10μs 펄스를 낸다.
     delay()를 쓰지 않는 방식이라 그동안에도 버튼·신호 확인이 계속 돈다.

 [시리얼 명령]  (115200bps, 줄 끝 "새 줄")
  ?      현재 상태 출력 (모드, 잠김 이유, 현재·목표 속도 등)
  N800   자동 속도를 800 스텝/초로      S300   저속 속도를 300 스텝/초로
  A1500  가속도를 1500 스텝/초²로       D      회전 방향 반대로
  T      시험 모드 켜기/끄기. 켜면 micro:bit 입력과 살아 있음 신호를 무시하고
         시리얼로 모드를 정한다. 끄면 다시 POWERON 잠김이 된다.
  1~4    (시험 모드에서만) 모드 지정. 1 자동, 2 저속, 3 정지, 4 잠금
  R      (시험 모드에서만) 잠김 해제
  시리얼로 바꾼 값은 전원을 끄면 사라진다. 정한 값은 코드 위쪽 상수에 적어 둘 것.

 [주요 설정값]  (파일 위쪽 "설정" 부분)
  NORMAL_SPS, SLOW_SPS  속도 (TB6600 마이크로스텝 설정에 따라 실제 속도가 달라짐)
  ACCEL_SPS2            가속도
  DIR_FORWARD           회전 방향
  USE_ESTOP_SENSE       비상정지 보조 접점을 D11에 배선했으면 true
  USE_RELAY / RELAY_ACTIVE_HIGH  릴레이 사용 여부와 동작 레벨
  ENA_ENABLE_LEVEL      드라이버를 켜는 ENA 레벨 (TB6600은 보통 LOW)


----------------------------------------------------------------------
 7. 안전 설계 요약
----------------------------------------------------------------------

 - 멈추는 경로가 여러 개다.
   ① 사람 접근(정지 거리) → 손 3이 일시 정지로 바꿈 → 모든 기기·벨트 정지
   ② 손 3이 꺼지거나 고장 → 살아 있음 신호 끊김 → 손들과 벨트가 스스로 정지
   ③ 게이트웨이 선이 빠짐 → 아두이노가 LOCK + 신호 끊김으로 읽고 정지·잠김
   ④ 비상정지 버튼 → 드라이버 전원을 직접 끊음 (프로그램과 무관하게 배선)
 - 멈춘 뒤 저절로 다시 돌지 않는다.
   · 사람 접근 정지 뒤에는 카드 1·2를 "새로" 보여 줘야 출발한다.
   · 아두이노 잠김은 리셋 버튼으로만 풀린다.
 - 정지는 감속 없이 즉시, 출발은 천천히 한다.
 - 노트북은 정지 경로에 없다. 판정과 기록만 맡는다.

 ※ 교육용 시제품이며 산업 안전 인증 장비가 아니다.

 8. 업로드 방법과 배선
----------------------------------------------------------------------

 8.1 micro:bit (손 1~4, 게이트웨이)

  1) https://makecode.microbit.org 접속 → 새 프로젝트
  2) 톱니바퀴 → 확장(Extensions) → 아래 주소를 검색해 추가
       손 1~4 : https://github.com/Hiwonder/StartbitV2
       손 3만 : https://github.com/Hiwonder/WonderCam   (추가로)
       게이트웨이 : 추가할 확장 없음
  3) 위쪽 "JavaScript" 탭을 열고, 기존 내용을 지운 뒤 해당 .ts 파일 내용
     전체를 붙여넣는다.
     (손 1·2는 붙여넣은 뒤 HAND_ID 값을 1 또는 2로 바꾼다)
  4) "다운로드"를 눌러 받은 .hex 파일을 MICROBIT 드라이브에 복사한다.
     Chrome·Edge에서는 WebUSB 페어링으로 바로 업로드할 수도 있다.
  5) 모든 기기의 RADIO_GROUP 값이 같은지 확인한다.
     같은 공간의 다른 팀과 겹치면 모두 같은 다른 값으로 바꾼다.

  ※ 블록 탭으로 바꾸면 일부가 회색 블록으로 보일 수 있다. JavaScript 탭에서 수정한다.
  ※ 로봇 손은 7.5V 어댑터를 연결해야 서보가 움직인다.

 8.2 아두이노

  Arduino IDE에서 conveyor/conveyor.ino를 열고 보드를 "Arduino Uno"로 골라
  업로드한다. 추가 라이브러리는 필요 없다.
  명령줄: arduino-cli compile --fqbn arduino:avr:uno conveyor
          arduino-cli upload  --fqbn arduino:avr:uno -p COM포트 conveyor

 8.3 배선

  게이트웨이 micro:bit → 아두이노 (악어클립 또는 엣지 커넥터)
    P0  → D6      P1  → D7      P2  → D8      GND → GND (반드시 연결)

  아두이노 → TB6600 (공통 음극 방식)
    D3 → PUL+     D4 → DIR+     D5 → ENA+
    PUL-, DIR-, ENA- → 아두이노 GND
    TB6600 전원(VCC/GND) ← 24V 전원 (비상정지 버튼을 이 선에 직렬로)
    TB6600 A+/A-/B+/B- ← 스텝모터

  버튼
    리셋 버튼: D10 ↔ GND
    (선택) 비상정지 보조 접점: D11 ↔ GND (평소 닫힘), 코드에서 USE_ESTOP_SENSE = true
    (선택) 릴레이: 모듈 IN → D12, 코드에서 USE_RELAY = true

  전압 주의
    micro:bit는 3.3V, 아두이노 우노는 5V다. 이 구성은 micro:bit가 아두이노로
    출력만 하므로 그대로 연결해도 된다 (3.3V는 우노에서 HIGH로 읽힘).
    반대로 아두이노 출력을 micro:bit 핀에 직접 넣으면 안 된다.


----------------------------------------------------------------------
 9. 보정 (실물에 맞춰 값 조정)
----------------------------------------------------------------------

 코드 안의 ★ 표시 값은 실물에서 확인하지 않은 임시값이다.

 1) 손 1·2 날개판
    - 먼저 손목을 돌렸을 때 날개판이 벨트 위에서 수평으로 도는지 확인한다.
    - WRIST_PARALLEL: 날개판이 벨트 가장자리와 나란해지는 각도
    - WRIST_DIVERT  : 날개판이 벨트를 30~45°로 가로막는 각도
                      (날개판 끝이 벨트 반대쪽 가장자리에 닿아야 병이 빠져나감)
    - REST_*        : 손가락이 손목 고정 장치와 부딪히지 않는 쉬는 자세
    - 병이 날개판을 밀어도 장치가 손목에서 돌거나 흔들리지 않는지 확인한다.
    - 각도를 맞출 때는 일시 정지 상태에서 A(비스듬히)·B(나란히) 버튼으로
      두 위치를 번갈아 확인할 수 있다.
 2) 손 3 접근 거리
    - 초음파 앞으로 손을 천천히 가져가며 WARN_MM / STOP_MM을 정한다.
    - 초음파는 벨트 쪽 접근 경로를 향하게 둔다. 카드를 보여 주는 위치가
      초음파 정면이면 카드를 내밀 때마다 정지가 걸린다.
 3) 벨트 속도
    - 아두이노 시리얼 모니터에서 T → R → 1 순서로 시험 모드 출발.
    - N, S 명령으로 속도를 바꿔 보며 정하고, 출발 때 모터가 떨면 A 값을 낮춘다.
    - 정한 값을 코드의 NORMAL_SPS / SLOW_SPS에 적어 다시 업로드한다.


----------------------------------------------------------------------
 10. 시험 순서
----------------------------------------------------------------------

 재료가 다 갖춰지지 않아도 앞 단계부터 따로 시험할 수 있다.

 1) 손 단독
    손 1에 업로드 → A로 비스듬히, B로 나란히 손목이 도는지 확인.
    손 3이 없으니 "?"가 뜨는 것이 정상이다.
 2) 손 3 + 손 4
    카드 1~5를 보여 주고 손 3이 복창하고 손 4가 따라 하는지 확인.
    손 3 전원을 끄면 2초 안에 손 4에 "?"가 떠야 한다.
 3) 게이트웨이 + 손 1·2 (+ 손 3)
    손 3에 카드 1 → 게이트웨이 버튼:
    A(유색)는 손 1이 비스듬히, B(내용물)는 손 2가 비스듬히,
    A+B(적합)는 둘 다 나란히.
 4) 아두이노 단독
    시리얼 시험 모드로 속도·방향 확인.
 5) 전체
    게이트웨이 핀 연결 → 리셋 버튼 → 카드 1(벨트 출발) → 카드 3(정지)
    → 손 3 끄기(벨트 정지·잠김) → 손 3 켜고 리셋 → 카드 1(재출발).
    노트북에서 J0~J4를 보내 분기까지 확인한다.


----------------------------------------------------------------------
 11. 알려진 한계와 미확정 사항
----------------------------------------------------------------------

 - 검증 상태
   아두이노 코드는 컴파일까지 확인했다 (Uno 기준 프로그램 공간 약 25%).
   micro:bit 코드는 Hiwonder 확장 소스와 대조해 작성했지만,
   실물 업로드와 동작 시험은 아직 하지 않았다.
 - 병 투입 간격
   날개판은 판정을 받는 즉시 움직이고 다음 판정이 올 때까지 그 자세를
   유지한다. 따라서 검사 자리와 손 2 사이에는 병이 한 개만 있어야 한다.
   병이 더 촘촘하게 들어오려면 병별로 도착 시각을 계산하는 방식이 필요하다.
 - YOLO 판정 프로그램과 대시보드는 이 폴더에 없다. 5.4의 형식만 맞추면 연결된다.
 - 아래는 원래 팀 역할표에 없어서 임시로 정한 것이다. 팀 결정에 따라 바뀔 수 있다.
   · 게이트웨이 micro:bit 추가
   · 주의 거리에서는 경고만, 정지 거리에서는 일시 정지 + 카드로 재출발
   · 손 3 버튼 배정 (A 정지, B 도움 끄기, 로고 도움 켜기, A+B 잠금 해제)
   · 점검 잠금 해제는 손 3의 A+B
